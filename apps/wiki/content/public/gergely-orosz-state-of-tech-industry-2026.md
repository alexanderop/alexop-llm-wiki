Generating more code changes where engineering effort goes. In his [written summary of the keynote](https://newsletter.pragmaticengineer.com/p/the-state-of-the-tech-industry-in), Gergely Orosz describes engineers coordinating several agents while review and validation struggle to keep up.

## What the written summary argues

- **Work is changing.** Parallel agents, shared skills and company-specific agent infrastructure are becoming common in the organizations he covers.
- **Faster output creates pressure.** Review can become a formality, and switching between agents can make work more exhausting. He also reports concerns about reliability and infrastructure capacity.
- **Engineering responsibilities remain.** Teams still own software. Complex work still needs planning, tests and validation.
- **His forecast:** more cloud agents, less manual code reading, and greater value in domain knowledge. These are predictions, not established outcomes.

His examples focus on AI labs, venture-backed startups and Big Tech. They don't establish that every engineering team works this way.

## Connection to the wiki

**Agent interpretation:** [Agent verification loops](/notes/agent-verification-loops) offer a practical response to the validation problem: give the agent observable results to check. This connection doesn't establish that passing tests makes unread code safe to release.
